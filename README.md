# paper-knock — 論文ノック

論文を毎日1本読む習慣のための台帳。**1論文=1 Issue** で記録を積み、Issueの総数がそのまま読んだ本数のメーターになる。

## 読み方の2つの型

論文はすべて同じ深さで読まず、2つの型を使い分ける。

| 型 | 割合の目安 | 何をするか | ラベル |
|---|---|---|---|
| **ノック**(アブスト水準) | 8割 | 問題意識・手法・結果を自分の言葉で3行に書き、吟味コメントで締める。テーマの関心範囲を掴むのが目的 | `d: アブスト` |
| **精読** | 2割 | [a1da4/paper-survey](https://github.com/a1da4/paper-survey) の7セクション形式で書く。構成(各節の分量配分)まで把握し、テーマの土地勘と重要パートを掴むのが目的 | `d: 精読` |

ノックした論文は後から精読へ格上げできる(同じIssueの本文を7セクションへ拡張し、ラベルを付け替える)。

## 状態の表し方

- **Issueはcloseしない**。すべてopenのまま積む。
- 読み中の論文には **`zz: reading`** ラベルを付け、読了(吟味コメントの投稿)と同時に外す。`zz:` 接頭辞はアルファベット順で最後になるため、ラベル列の右端に固定表示される。
- したがって `label:"zz: reading"` = いま読んでいる山、付いていないIssue = 読了。

## 1本の流れ

1. **起票**: 読む論文が決まったら、書誌(`Paper`)を埋めたIssueを `zz: reading` ラベル付きで作る。考える部分は空欄で置く。
2. **本文**: 問題意識・手法・結果の3行を **自分の言葉で** 書く(コピペしない)。問題意識は明文化して腑に落ちるまで。
3. **吟味**: 読了の締めとして **吟味コメント** を1本投稿する。3問に答える —
   - **クリティカルか**: この問題が未解決だと誰が何に困るか。なぜ非自明か
   - **手段として適切か**: 設計が測っているものは問題意識と一致しているか
   - **答え切ったか**: 主張の強さは証拠に見合っているか
   書式は各問を `###` 見出し・答えを本文にする(問いと答えを同じ大きさで並べない)。
4. **読了処理**: `zz: reading` ラベルを外し、索引と進捗表を更新する。

## 運用ルール

- **ペース: 平日ノック2本+精読 週2本**。
- 選書は自分の目で行う(alphaXiv・arXiv新着・curated list)。推薦機能に任せない。
- 索引= [knocks.md](knocks.md)(番号・タイトル・Issueリンクの一覧のみ。本文はIssueにだけ書く)。索引と進捗表の更新はmainへの直コミットで行い、PRは使わない。
- **分担**: 読む・書くのは本人(green-caviar)。起票(書誌の検収込み)と索引・進捗表の更新はAIアシスタントが代行するが、Issueと本文は本人名義。AIアシスタント自身の発言(議論への返し)だけ **green-caviar-bot** 名義で投稿し、アイコンで発言者が区別できる。

## ラベル

接頭辞で系統を分ける。命名は小文字が既定(略語・固有表記のみ大文字)。必要になった時に追加する。

| ラベル | 意味 | 例 |
|---|---|---|
| `c:` | 出典・会議 | `c: arXiv`・`c: EMNLP` |
| `t:` | トピック | `t: agent`・`t: LLM` |
| `y:` | 年 | `y: 2025` |
| `d:` | 読解深度 | `d: アブスト`・`d: 精読` |
| `z:` | 補助 | `z: survey` |
| `zz: reading` | いま読んでいる(読了で外す・常に右端) | — |

補助にラベル `😃favorite`(お気に入り)・`🤔???`(消化しきれていない)も使う。

## テンプレート

### ノック(`d: アブスト`)

```markdown
## Paper

(書誌: タイトル・著者・venue/年・alphaXiv・arXiv)

## 問題意識

## 手法

## 結果

```

### 精読(`d: 精読`・[a1da4/paper-survey](https://github.com/a1da4/paper-survey) 形式)

```markdown
## 0. Paper

(書誌: タイトル・著者・venue/年・alphaXiv・arXiv)

## 1. What is it?

## 2. What is amazing compared to previous works?

## 3. Where is the key to technologies and techniques?

## 4. How did evaluate it?

## 5. Is there a discussion?

## 6. Which paper should read next?

## 7. personal comment

```
